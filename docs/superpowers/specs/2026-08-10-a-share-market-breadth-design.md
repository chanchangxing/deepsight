# 沪深 A 股累计涨跌差值网站设计

## 目标

构建一个公开访问的单页数据网站，从 2025 年 1 月 1 日起展示上证指数与沪深 A 股累计涨跌差值之间的关系。网站在每个交易日收盘后自动更新，并允许手动补跑。

核心指标不是单日涨跌家数差，而是从起始日期开始连续累加的市场广度指标：

```text
单日涨跌差值 Dₜ = 当日上涨股票数 − 当日下跌股票数
累计涨跌差值 Nₜ = Nₜ₋₁ + Dₜ
N₀ = 0
```

等价地，某日的 `N` 是从起始日到该日所有 `D` 的总和。

## 数据范围与口径

### 日期

- 起始边界为 2025 年 1 月 1 日，实际首条记录为该日期之后的首个沪深交易日。
- 仅保存正式交易日；周末和休市日不生成记录。
- 交易日以当日是否存在上证综合指数正式日线数据为准。
- 自动更新在北京时间每个工作日 15:30 后触发；任务仍会检查交易日，避免节假日产生数据。

### 股票范围

纳入上海证券交易所和深圳证券交易所 A 股，包括沪市主板、科创板、深市主板和创业板。ST 与 `*ST` 股票正常纳入。

排除北交所股票、B 股、基金、ETF、LOF、债券、可转债和指数。停牌或缺少有效收盘价的股票不进入当日上涨、下跌或平盘统计。上市首日若没有可比较的前一交易日收盘价，也不进入当日统计。

历史统计按股票在对应交易日的实际状态计算。后来上市的股票只从第二个有效交易日开始纳入；后来退市的股票在退市前仍保留其历史统计。

### 涨跌判断

使用不复权日线收盘价：

- 当日收盘价大于前一有效交易日收盘价：上涨。
- 当日收盘价小于前一有效交易日收盘价：下跌。
- 当日收盘价等于前一有效交易日收盘价：平盘。

平盘单独记录，不进入 `D`。不使用复权价格，以防未来公司行为反向改变已经发布的历史统计。

### 上证指数

采用上证综合指数 `000001` 的不复权日线，保存收盘点位、涨跌点数和涨跌幅。涨跌点数及涨跌幅统一根据相邻交易日收盘点位计算。

## 数据存储

数据存放在 GitHub 仓库内，不引入独立数据库：

- `data/market_history.csv` 是可审阅、可下载的长期主数据。
- `public/data/market_history.json` 由 CSV 生成，供网站直接读取。

每个交易日一条记录，字段为：

```text
date
shanghai_close
shanghai_change
shanghai_change_pct
up_count
down_count
flat_count
valid_count
daily_diff
cumulative_diff
```

`daily_diff` 对应 `D`，`cumulative_diff` 对应 `N`。每次生成 JSON 时，程序按日期排序并从零重新计算全部 `N`，而不是仅依赖上一条记录中的累计值。历史日期被补录或修订后，后续累计值会自动同步更新。

采集期间的逐股票缓存属于可丢弃的构建数据，不作为网站发布数据提交。

## 自动采集与发布

GitHub Actions 在每个工作日北京时间 15:30 后运行 Python 采集程序。程序通过 AKShare 获取上证指数日线与沪深 A 股行情，完成校验、更新 CSV、重新计算累计值并生成 JSON。

流程为：

```text
定时或手动触发
→ 获取 AKShare 数据
→ 判断是否为交易日
→ 计算当日上涨、下跌、平盘和单日差值
→ 更新当日记录
→ 按日期重算全部累计值
→ 执行完整校验
→ 提交数据变更
→ 触发静态网站重新发布
```

同一日期重复运行时更新该日期，不重复追加。日常任务会重新计算最近 5 个交易日，以吸收上游行情修订。另提供手动全量模式，用于回溯或重新生成 2025 年以来的数据。

GitHub 定时任务可能因平台负载延迟，因此目标是收盘后自动完成，而非承诺固定分钟发布。

## 校验与错误处理

发布前必须满足：

- 日期是有效交易日，且上证指数存在正式收盘数据。
- 股票具有可比较的当日与上一有效交易日收盘价。
- `up_count + down_count + flat_count = valid_count`。
- `daily_diff = up_count - down_count`。
- `cumulative_diff` 等于从首日至当前日期全部 `daily_diff` 的和。
- 日期唯一并严格递增。
- 当日有效股票数量没有相对近期水平出现无法解释的异常下降。

任一关键校验失败时，任务以失败状态结束，不提交 CSV 或 JSON，网站继续展示上一版有效数据。网站显示数据截至日期和最后更新时间，不用零值填补缺失日期。

## 网站页面

网站采用响应式单页数据看板，首屏直接呈现核心市场广度信息，不设置通用后台导航。

页面包括：

1. 标题、数据截至日期和更新状态。
2. 指标卡：上证指数、当日上涨数、当日下跌数、当日差值 `D`、累计值 `N`。
3. 双轴主图：上证指数与累计涨跌差值 `N` 共用时间轴，用不同颜色和线型展示。
4. 辅助柱状图：展示每日单日涨跌差值 `D`，正值红色、负值绿色。
5. 时间范围选择：近 1 月、3 月、6 月、1 年和全部。
6. 统计口径说明与 CSV 下载入口。

图表支持鼠标悬浮和触摸查看，提示框显示当日完整数据。手机端采用纵向布局并保持图表可读性。视觉使用浅色背景、深色文字以及 A 股习惯的红涨绿跌；上证指数和累计曲线必须易于区分。

## 技术边界

- 数据处理使用 Python 与 AKShare。
- 网站为静态前端，只消费已验证的 JSON，不在浏览器中调用 AKShare。
- 自动调度与数据提交使用 GitHub Actions。
- 公开发布采用静态网站托管，代码提交后自动重新构建。
- 不加入用户账户、实时盘中刷新、选股或交易建议功能。

## 测试与验收

数据层验证包括涨跌分类、累计公式、重复日期覆盖、非交易日跳过、缺失行情排除、历史修订后的全量重算以及异常数据阻止发布。

前端验证包括 JSON 加载失败状态、时间范围切换、双轴图与柱状图数值、提示框、CSV 下载、桌面和手机布局。

项目验收条件：

- 数据从 2025 年首个交易日开始。
- `N` 与全部历史 `D` 的累计和一致。
- 上证指数与市场广度在同一时间轴上清晰展示。
- 自动任务可定时运行，也可手动补跑。
- 重复运行不产生重复数据。
- 采集或校验失败时不发布错误数据。
- 网站具有可公开访问的地址，并能在数据提交后自动更新。
